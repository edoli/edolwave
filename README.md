# EdolWave

Rust + GPUI로 만든 Windows 네이티브 오디오 플레이어입니다. 웹뷰 없이 GPU로 화면을 그리고, 파일 읽기·오디오 장치 초기화·탐색·파형 분석은 UI 스레드 밖에서 처리합니다.

## 실행

Windows 10/11, Rust 1.96 이상, Visual Studio C++ Build Tools와 Windows SDK가 필요합니다.

```powershell
cargo run --release
# 파일을 바로 열기 (여러 파일도 가능)
cargo run --release -- "D:\Audio\confirm.wav"
```

빌드가 끝나면 `target\release\edolwave.exe`를 직접 실행하세요. Cargo의 컴파일 시간은 앱의 실행 시간과 별개입니다. 첫 빌드는 GPUI 의존성 때문에 시간이 걸립니다.

## 화면과 조작

- 어두운 남색 화면과 파일명, 파형을 표시합니다. 현재 시간과 전체 시간은 같은 크기로 정렬하고, 전체 파일 경로는 하단 왼쪽, 오디오 정보는 하단 오른쪽에 표시합니다.
- 재생 버튼은 다른 전송 버튼과 같은 둥근 직사각형이며 파란색으로 강조합니다.
- 제목 영역은 52px, 재생 관련 버튼은 44×32px, 시간 글자는 16px로 구성했습니다. 제목과 그 주변 빈 영역은 Windows 기본 창 이동 영역으로 동작합니다.
- 별도의 재생 위치 슬라이더 없이 파형을 클릭하거나 드래그합니다. 드래그 중 위치를 미리 보고, 놓으면 해당 위치로 이동합니다.
- 재생한 파형은 선명한 파란색, 남은 파형은 옅은 청회색입니다.
- 파형은 촘촘한 피크 데이터에서 연속 형태를 만들고, 별도의 테두리와 그라데이션 없이 단색으로 그립니다. 파일·크기·DPI가 바뀔 때만 도형을 다시 계산합니다.
- 배속은 0.5–2.0배의 일곱 눈금 사이에서 0.25배 단위로 선택하는 슬라이더입니다. 눈금을 클릭하거나 드래그하면 가장 가까운 단계로 맞춰집니다.
- 최소 창 너비는 480px입니다. 820px 미만에서는 조작부를 두 줄로 배치합니다.
- 드래그 후에는 오디오 작업 스레드가 해당 탐색의 완료를 알릴 때까지 선택한 위치를 유지하므로 이전 위치로 순간적으로 되돌아가지 않습니다.
- 재생/일시정지, 정지, 이전/다음, 볼륨·음소거, 0.5–2배속, 현재 파일 반복.
- 폴더 아이콘이나 `Ctrl+O`로 파일을 열거나 창에 파일을 끌어놓으세요. 여러 파일을 열면 재생 목록 순서대로 이동하며 다음 파일을 자동 재생합니다.
- 제목 영역을 드래그하면 창이 이동하고, 두 번 클릭하면 최대화합니다. 톱니바퀴에서 조작 안내를 볼 수 있습니다.

| 키 | 동작 |
| --- | --- |
| Space | 재생 / 일시정지 |
| Ctrl+O | 파일 열기 |
| ← / → | 5초 뒤 / 앞 탐색 |
| Home | 처음으로 |
| ↑ / ↓ | 볼륨 5% 조절 |
| M / R | 음소거 / 반복 |
| Escape | 안내 닫기 / 드래그 취소 |
| Ctrl+Q | 종료 |

배속은 재생 샘플 속도를 바꾸므로 음높이도 함께 바뀝니다. 반복은 파일 끝에서 다시 재생하며, 샘플 단위의 끊김 없는 루프는 보장하지 않습니다.

디코더가 특정 위치의 탐색을 거부하면 새 디코더에서 해당 위치까지 순차 디코딩해 복구합니다. 이 대체 경로는 긴 압축 파일에서 시간이 더 걸릴 수 있으며, UI는 계속 반응합니다.

## 오디오 형식

기본 엔진은 Rodio의 Symphonia 전체 코덱 기능을 사용합니다. WAV/PCM, MP1/MP2/MP3, FLAC, OGG/Vorbis, AAC-LC, MP4/M4A(ALAC/AAC), AIFF, CAF, MKV/WebM의 지원 오디오 트랙 등을 외부 실행 파일 없이 읽습니다. 컨테이너의 확장자만으로 모든 내부 코덱이 지원되는 것은 아닙니다.

기본 디코더가 읽을 수 없는 Opus, WMA, APE, WavPack, AC3 등은 **FFmpeg가 설치되어 있으면** 자동으로 임시 PCM WAV로 변환합니다. 이 경우 첫 재생에 변환 시간이 추가되고 임시 디스크 공간이 필요합니다. FFmpeg가 없어도 기본 지원 형식은 정상 동작하며, 지원되지 않는 파일에는 오류를 표시합니다. DRM 파일은 지원하지 않습니다.

FFmpeg는 PATH에서 찾거나 다음 환경 변수로 지정할 수 있습니다. 설치된 FFmpeg 빌드가 제공하는 코덱 범위 안에서 동작합니다.

```powershell
$env:EDOLWAVE_FFMPEG = 'C:\Tools\ffmpeg\bin\ffmpeg.exe'
.\target\release\edolwave.exe
```

FFmpeg는 앱에 포함하지 않습니다. 변환 파일은 앱이 더 이상 사용하지 않을 때 삭제합니다. 프로세스가 강제로 종료되면 운영체제 임시 폴더에 `edolwave-*.wav`가 남을 수 있습니다.

## 빠른 시작을 위한 구조

- 창을 먼저 만들고 오디오 엔진은 별도 스레드에서 동작합니다. 시작할 때 폴더 검색이나 전체 파일 디코딩을 하지 않습니다.
- 기본 형식은 스트리밍 디코딩으로 바로 재생합니다. 파형 생성 완료를 기다리지 않습니다.
- 오디오 출력에 512 프레임 버퍼를 요청하며 장치가 지원하지 않으면 지원 설정으로 대체합니다. 실제 지연은 장치·드라이버에 따라 달라집니다.
- 파형은 최대 8,192개 중간 피크와 2,048개 표시 피크만 유지합니다. 전체 PCM을 메모리에 쌓지 않습니다. 긴 파일의 분석 시간은 파일 길이에 비례합니다.
- 새 파일을 열면 이전 파형 분석을 취소하고, 이전 결과가 현재 파일에 적용되지 않도록 구분합니다.
- 재생 중 화면 갱신은 약 30fps이며, 정지 상태에서는 변경된 내용이 있을 때만 다시 그립니다.
- 릴리스 빌드에는 Thin LTO, 단일 코드 생성 단위, 심볼 제거를 적용했습니다.

선택적으로 첫 UI 렌더 시점을 기록할 수 있습니다. 측정 범위는 `main()` 진입부터 첫 렌더 함수 호출까지이며, 프로세스 로더나 실제 화면 표시 완료 시간은 포함하지 않습니다.

```powershell
$env:EDOLWAVE_STARTUP_LOG = "$PWD\startup.txt"
.\target\release\edolwave.exe
```

## 검증

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
# 실제 출력 장치로 재생·일시정지·탐색·반복·오류 복구 검증 (낮은 볼륨)
cargo test --test audio_flow -- --ignored --nocapture
# FFmpeg로 다양한 형식의 테스트 파일을 만들고 실제 출력 검증
.\scripts\verify-formats.ps1
# Python으로 UI 클릭·드래그·키 입력·최소 창 크기 검증 및 스크린샷/시작 시간 기록
# 검증 도구 의존성: Pillow, pywin32, numpy
python scripts\verify-ui.py
# 재생 중 탐색을 60회 반복하며 마우스를 놓은 직후의 진행선도 검증
python scripts\verify-ui.py --benchmark-runs 2 --seek-stress 60
```

`src/main.rs`: 창과 앱 진입점, `src/ui.rs`: GPUI UI와 조작, `src/audio.rs`: 오디오 작업 스레드와 FFmpeg 대체 처리, `src/waveform.rs`: 메모리 사용량을 제한한 파형 분석, `src/waveform_view.rs`: 파형 도형 캐시와 GPU 렌더링, `src/assets.rs`: 실행 파일에 포함하는 SVG 아이콘.

이 환경에서 릴리스 실행 파일은 약 8 MB이며, 최종 빌드 반복 실행 2회의 `main()` 진입부터 첫 렌더까지 약 700–701 ms로 측정했습니다. Python 검증 결과는 `.artifacts/ui/report.json`과 같은 폴더의 PNG에 저장합니다. 검증창 자체를 캡처하므로 다른 창이 앞에 있어도 검증할 수 있습니다. 측정값은 장치·드라이버·캐시 상태에 따라 달라집니다.
